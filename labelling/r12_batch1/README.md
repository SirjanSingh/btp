# R12 batch 1 — 30 Jaipur crops for hand-labelling

Generated by `scripts/r12_select_label_tiles.py --n 30 --seed 42`.
Regenerate with the same seed to get the identical selection.

## Why this batch exists

Every Jaipur number in this repo — every IoU, every merge rate, the 0.6393
headline — measures **agreement with Google Open Buildings**, not accuracy.
Open Buildings is itself a model's output, and it traces **ground footprints,
not roof outlines**. Until some tiles are labelled by hand, three results cannot
be interpreted at all:

- **R3** (label-confidence sweep) is circular — each model wins on its own
  label distribution.
- The **merge rate** has no true value to be measured against, only an OB-derived one.
- Every IoU quoted anywhere is agreement, and should be described that way.

30 crops is small, but it is the difference between *no* answer key and one.

## The one rule

> **Draw the masks without opening `openbuildings_reference/`.**

That directory holds the Open Buildings mask for each crop. It is shipped so the
two can be *compared afterwards* — that comparison is the entire result. If it
is used as a starting canvas, the hand labels will agree with OB by construction
and the question "how wrong is OB?" becomes unanswerable. `labels/` therefore
ships empty, on purpose.

If a crop is genuinely ambiguous, mark it in `notes` rather than peeking — an
ambiguity rate is itself a finding.

## Layout

```
working/     20 crops — iterate against these freely
  images/                  the RGB crop, 512x512
  labels/                  ← draw here, same filename, binary PNG (255 = roof)
  openbuildings_reference/ do not open until labelling is done
sealed/      10 crops — same structure; DO NOT LOOK until the method is frozen
manifest.csv            per-crop density bin, parent tile, OB building count
selection_summary.json  how the sample was drawn
```

## What counts as a roof

Decisions worth fixing now, because inconsistency here is indistinguishable
from model error later:

- Label the **roof outline as seen from above**, not the building's ground
  footprint. Where a roof overhangs, follow the roof. This is precisely where
  OB is expected to disagree.
- Adjacent buildings that touch get **separate** regions with a visible gap —
  the count is what feeds the per-building kW estimate, and 78 % of Jaipur
  buildings touch a neighbour (D4).
- Roof superstructures (stairwells, water tanks) stay **inside** the roof
  polygon for this pass. Marking them as a third class is a later, optional
  pass — see the `k_usable` note in the UDA memory.
- Under-construction slabs with walls count; bare foundations do not.
- Six crops are **empty** by OB's reckoning. They are in the batch deliberately:
  they are the only direct measure of false-positive rate. If you find a
  building in one, that is a result — record it.

## Stratification

Equal allocation across five density bins rather than proportional sampling,
because the rare regimes are the informative ones and a uniform draw of 30 would
miss both tails.

| bin | OB fg fraction | pool | selected |
|---|---|---|---|
| empty | 0 | 833 | 6 |
| sparse | 0–0.15 | 2,344 | 6 |
| moderate | 0.15–0.27 | 2,015 | 6 |
| dense | 0.27–0.36 | 1,626 | 6 |
| very_dense | ≥ 0.36 | 2,254 | 6 |

All 16 parent tiles are represented; within a bin, crops are drawn from distinct
tiles first, since adjacent crops share content and would inflate agreement.

## When labels exist

```bash
python scripts/merge_split_rate.py --pred <model_masks> --gt labelling/r12_batch1/working/labels
```

Report **IoU, merge rate, split rate and `pred/label`** together — IoU alone is
misleading for this project. Then run the same comparison with
`openbuildings_reference/` as the prediction: that number is the honest error
bar on every weakly-supervised result in the repo.
